# Server configuration

Time windows use real-server ticks and `_ticks` names. Seconds below assume 20 TPS; lag can lengthen wall-clock waits. Packet simulation tick numbers are separate from these timeout counters. Positive integer windows are required except where 0 explicitly disables a feature. MB means 1,000,000 bytes throughout these settings. Zero is not an unlimited value unless the setting explicitly says so.

## Admission and ownership

Server settings may be overridden in `config/coworld-server.properties`:
`offload_enabled`, `max_sub_servers`, `max_ping`, `high_ping_ticks`,
`max_ownership_radius`, `sync_speed_limit`, `handshake_hello_timeout_ticks`,
and `ping_probe_timeout_ticks`. Integer values must be nonnegative; malformed
files fail at server startup. Client settings may be set in
`config/coworld-client.properties` with `offloading=true|false` and
`disk_allowance=<nonnegative bytes>`. A malformed client config fails closed
by disabling offloading for that connection.

- `offload_enabled`: Boolean master switch. When false, decline new offloading and request normal hand-back from existing owners; players continue through the real server. Transfers still obey the occupied-chunk and failure rules. **Default:** true.
- `max_sub_servers`: Maximum simultaneous sub-server instances, including startup and hand-back. A new instance at the cap is declined, without kicking its player. **Unit:** instances. **Default:** 20.
- `max_ping`: Maximum accepted round-trip time. Handshake uses the median of three completed probes. A value equal to the limit passes; only a larger value fails. Ongoing monitoring uses Minecraft's built-in player ping measurement. **Unit:** milliseconds. **Default:** 70 ms.
- `high_ping_ticks`: Consecutive real-server ticks for which the current monitored ping must exceed `max_ping` before hand-back begins. A measurement at or below the limit resets the counter. **Default:** 100 (5 seconds).
- `max_ownership_radius`: Nonnegative integer cap, in chunks. Requested radius is the minimum of this cap and client simulation distance. The square includes offsets satisfying `abs(dx) <= radius` and `abs(dz) <= radius`. A radius of 0 disables offloading for that client. Claims, unmodded-player occupied-chunk rule, and whole-redstone-set rules constrain actual ownership; redstone sets may extend beyond the square. **Default:** 8.
- `vanilla_player_handover_release_distance`: Positive integer distance, in chunks, for releasing an unmodded-player-occupied chunk when its old sub-server owner's player moves away. Measure `max(abs(dx), abs(dz))` from that old owner's player chunk to the occupied chunk in the same dimension, not from a prospective new owner. Strictly greater than the threshold permits transfer to the real server or another eligible sub-server; equality remains protected. The real server has no owner-player position and cannot qualify through this distance exception alone. Moving and stationary occupants have the same rule. One occupied member pins a whole redstone set unless every occupied member qualifies for release. Clean shutdown, failure reclaim, and required redstone consolidation remain exceptions. **Default:** 12.
- `redstone_takeover_max_chunks`: Maximum number of distinct chunks in a transferable redstone set. Equality is allowed; larger sets stay entirely server-owned. **Unit:** chunks. **Default:** 64.

## Transfer and liveness

- `sync_speed_limit`: Nonnegative integer cap in bytes/second per client for combined mods/config/runtime/player/world sync traffic, including snapshot/resync data. 0 disables throttling; negative or noninteger values are invalid configuration. Count compressed transmitted payload bytes, not uncompressed content or file sizes. All sync streams share one token bucket per client: for a positive limit L, capacity and initial balance are L bytes, and refill is L bytes per elapsed monotonic second, capped at L. Debit bytes before transmission, retaining fractional refill credit. Split large transfers into budget-sized parts; no packet bypasses the cap or drives the balance negative. This allows at most one second of saved allowance, not a fixed calendar-second window. Gameplay inputs, live deltas, and heartbeats bypass this sync bucket. Sent in Accept. **Default:** 10,000,000 bytes/s (10 MB/s).
- `handshake_hello_timeout_ticks`: Wait from login for Hello before treating the connection as a normal non-offloading client. **Default:** 100 (5 seconds).
- `ping_probe_timeout_ticks`: Maximum wait for each of the three handshake probe replies. An expired or invalid probe declines offloading; do not invent a ping sample or continue with fewer than three. **Default:** 100 (5 seconds).
- `handover_offer_timeout_ticks`: Maximum time for one uncommitted handover attempt. The real server starts the counter when it creates the attempt and sends its first offer; receipt, readiness, retransmissions, and repeated messages do not reset it. At expiry, an uncommitted attempt aborts and the old owner retains authority. A fresh attempt has a fresh counter. Clean disconnect retries indefinitely while the connection survives, with no attempt-count limit or overall shutdown deadline. Each fresh attempt has its own timeout; an expired attempt never discards unconfirmed state. Connection loss follows [disconnect recovery](disconnect.md). **Default:** 100 (5 seconds).
- `disconnect_grace_ticks`: Wait after player inputs are cut before clean hand-back starts. The sub-server continues its owned simulation during this wait. **Default:** 20 (1 second).
- `resend_history_ticks`: Maximum age of retained complete result batches, measured in real-server ticks from retention insertion. Evict a batch when its age reaches the limit. **Default:** 200.
- `resend_history_bytes`: Maximum retained encoded result-batch bytes per producing simulator across all its chunks, including bookkeeping needed to resend them. Evict oldest complete batches before exceeding this bound. A batch larger than the bound is not retained. Both history limits apply; either can remove a batch. The real server announces its tick counter for remote retention accounting; remote producers use the latest observed counter and still enforce the byte bound without new announcements. Missing history always falls back to a snapshot. **Default:** 64,000,000 bytes (64 MB).
- `disconnect_timeout_ticks`: Real-server ticks since the last valid advancing completed-cycle heartbeat before reclaiming a vanished owner's chunks. Start counting at the first ownership commit; only a valid advancing heartbeat resets the counter. See the [heartbeat contract](delta-sync.md#heartbeats-and-completed-cycles). Reclaim occurs when the counter reaches the limit. **Default:** 600 (30 seconds).

## Performance and verification

- `min_subserver_tps`: Minimum completed sub-server ticks per elapsed second over the measurement window. Equality passes; below the threshold fails. **Unit:** ticks/second. **Default:** 20.
- `subserver_tps_window_ticks`: Non-overlapping observation windows of this many real-server ticks. TPS is completed sub-server ticks divided by the window's actual elapsed seconds, not an assumption that the window lasted five seconds. Each failed window adds one chunk of session-local radius reduction. Successful windows do not remove that reduction. Effective requested radius is `max(0, min(client simulation distance, max_ownership_radius) - reduction)`; changing either distance does not clear the reduction. Reset it to zero only on a new accepted offloading session. At zero, hand back remaining ownership. Actual transfers obey the occupied-chunk and whole-set rules. **Default:** 100 (5 seconds at 20 server TPS).
- `player_handover_prediction_ticks`: Predicted time-to-crossing threshold, in simulation ticks. A crossing at or within the threshold starts player warm standby. **Default:** 40 (2 seconds).
- `handover_verification_ticks`: Logical ticks of post-transfer shadow comparison. 0 disables it. A mismatch selects the former owner's complete transfer-unit shadow snapshot and returns authority through coordinated recovery with fresh versions/generation, allowing debug-only rollback. See [handover](handover.md#optional-verification). **Default:** 0.

Resend history is bounded by both configured limits above. Correctness never depends on a retained delta; a full snapshot is the fallback. See [delta sync](delta-sync.md).
